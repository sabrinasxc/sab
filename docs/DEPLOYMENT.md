# Deployment Runbook

The application code is designed to remain in shadow mode until every external integration is configured and the acceptance tests pass.

## 1. Repository Security

This application stores no secrets in Git. Keep `.env.local` and production secrets outside source control.

Recommended before production: make the repository private and protect `main` with required CI checks.

## 2. Supabase

Create a Supabase project and apply migrations in order:

1. `0001_foundation.sql`
2. `0002_security_constraints.sql`
3. `0003_knowledge_and_agent_idempotency.sql`
4. `0004_gmail_draft_linkage.sql`
5. `0005_outbound_speaker_outreach.sql`

Configure Supabase Auth with the production application URL and create the initial owner user.

Required values:

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`
- `DATABASE_URL`

Generate a strong application encryption secret for `INTEGRATION_ENCRYPTION_KEY`. Do not reuse an OAuth client secret or database password.

## 3. OpenAI

Create a project-scoped OpenAI API key and set:

- `OPENAI_API_KEY`
- `OPENAI_MODEL`

The model is used for three separate passes: triage, decision, and response generation. Structured JSON output is validated by Zod before downstream use.

## 4. Google Cloud and Gmail

Create/configure a Google Cloud project with Gmail API and Pub/Sub enabled.

Create an OAuth web client. Add the deployed callback URL:

`https://YOUR_APP/api/integrations/gmail/callback`

Set:

- `GOOGLE_CLIENT_ID`
- `GOOGLE_CLIENT_SECRET`
- `GOOGLE_REDIRECT_URI`
- `GOOGLE_PUBSUB_TOPIC`
- `GOOGLE_PUBSUB_VERIFICATION_TOKEN`

Create the Pub/Sub topic configured in `GOOGLE_PUBSUB_TOPIC` and grant Gmail permission to publish to it according to Google's Gmail push-notification requirements.

Create a push subscription that sends to:

`https://YOUR_APP/api/webhooks/gmail?token=YOUR_VERIFICATION_TOKEN`

Gmail watch renewal is scheduled daily by the Inngest function `renew-gmail-watches`.

## 5. HighLevel

Create a private Marketplace app first. Configure only the scopes needed for the enabled functionality, including contact read and task creation.

Add the deployed callback URL:

`https://YOUR_APP/api/integrations/ghl/callback`

Set:

- `GHL_CLIENT_ID`
- `GHL_CLIENT_SECRET`
- `GHL_REDIRECT_URI`
- `GHL_INSTALL_URL`

`GHL_INSTALL_URL` must be the installation URL generated by the HighLevel Marketplace app. Do not hard-code a guessed authorization URL.

## 6. Inngest

Create an Inngest app and set:

- `INNGEST_EVENT_KEY`
- `INNGEST_SIGNING_KEY`

The deployed Inngest endpoint is:

`https://YOUR_APP/api/inngest`

Functions include Gmail history ingestion, incoming-email processing, scheduled follow-up checks, and Gmail watch renewal.

## 7. Vercel

Import this GitHub repository into Vercel.

Configure all environment variables in Production and Preview as appropriate. `AI_ACTIVE` and `AUTO_SEND_ACTIVE` must remain `false` during initial deployment.

Set:

- `NEXT_PUBLIC_APP_URL=https://YOUR_APP`
- `AI_ACTIVE=false`
- `AUTO_SEND_ACTIVE=false`

Deploy.

## 8. First Business

Sign in, open `/setup`, and create the organization and first business.

Then open `/settings` and keep:

- Business AI: off initially
- Business auto-send: off
- Autonomy level: 0 initially
- Mailbox AI: off until connection testing succeeds
- Mailbox auto-send: off

Connect Gmail and HighLevel from the command center.

## 9. Shadow Mode

After integrations pass basic connectivity tests:

1. Set global `AI_ACTIVE=true`.
2. Enable AI for one business and one mailbox.
3. Keep all auto-send switches off.
4. Use autonomy level 0 or 1.
5. Review every classification, decision, draft, CRM match, and approval.
6. Compare AI recommendations with actual human action for several days.

Do not enable guarded auto-send until acceptance tests pass and explicit business rules authorize the low-risk categories.

## 10. Guarded Autopilot

For a mailbox to auto-send, all relevant gates must allow it:

- global AI active
- global auto-send active
- business AI active
- business auto-send active
- mailbox AI active
- mailbox auto-send active
- autonomy level at least 2
- low/allowed risk
- confidence threshold met
- explicit matching business rule
- no duplicate action
- no prohibited financial/security category
- no approval requirement

High and critical-risk workflows remain human-controlled.
